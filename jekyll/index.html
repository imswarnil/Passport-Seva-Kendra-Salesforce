Passport Seva Kendra, rebuilt on Salesforce

A working model of how an Indian Passport Seva Kendra could run on Salesforce — one object carrying a full application lifecycle, staff queues that route themselves, and an audit trail that never rewrites history. Built solo, documented as it went.

The aim

Why this exists

Passport processing is a good stress test for a Salesforce data model: one long-lived record moves through many hands, each stage has a different owner, some of what's recorded is a legal declaration that must never quietly change, and every step needs a paper trail. This project builds that, end to end, on a Developer Edition org — not a toy CRM demo, a real object model with security, automation, and the people who'd actually use it.

Few objects, many fields

The whole application lifecycle lives on one object with a Status picklist and record types — not a new object per stage.

Automatic, not unattended

Every status change cascades its required side effects — queue routing, document checklists, passport minting — but a human still decides when to move the record forward.

Declared vs. current

What an applicant declared at submission is preserved even after their identity record changes later — because a passport is a legal instrument, not a live profile.
