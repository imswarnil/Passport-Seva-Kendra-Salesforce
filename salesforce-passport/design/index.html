Color

The Salesforce app's app-meta.xml sets its Lightning App Builder header color directly:

force-app/main/default/applications/Application_Management_Console.app-meta.xml
<brand>
    <headerColor>#1A2A5E</headerColor>
    <logo>app_application_mgmt</logo>
    <shouldOverrideOrgTheme>false</shouldOverrideOrgTheme>
</brand>

This site's _config.yml declares the same navy and gold as a brand: block, and assets/css/style.css stamps them into CSS custom properties at the top of the stylesheet:

salesforce-passport/assets/css/style.css
:root {
  --navy: #1A2A5E;
  --navy-dark: #101B42;
  --gold: #C9A227;
  --paper: #F7F5F0;
  --ink: #1c1f27;
  --muted: #5b6178;
  --border: #e6e2d8;
}

Why the same seven colors in both places? Because if a site's whole purpose is teaching a build, the teaching material should visibly belong to the project it's teaching — not look like a generic blog that happens to link to the app. Navy and gold read as "official document" rather than "SaaS marketing site," which fits a passport office better than the default Salesforce Lightning blue would have. One note of honesty: the org's second app, Passport_Validator, still carries an inherited #005EA5 header from before this palette was standardized — a small, tracked inconsistency rather than a hidden one.

Typography & voice

No webfont is loaded anywhere on this site. body uses the system UI stack — -apple-system, BlinkMacSystemFont, "Segoe UI", Helvetica, Arial, sans-serif — so every page renders in whatever font the reader's own OS already uses, with zero network requests spent on typography.

The writing follows the same restraint: short declarative sentences, real file paths cited inline (force-app/main/default/objects/…, never a made-up example), and a documentation tone rather than a marketing one. No superlatives — nothing here is "revolutionary" or "seamless." A claim like "region-based sharing is unimplemented" is more useful, and more honest, than a claim that everything works perfectly.

Component patterns

A small, reused set of patterns carries the whole site. Each one is demonstrated live below, in the same markup used throughout.

.card grid

A .grid of .card elements for feature or concept lists — used on the homepage for the six things this build teaches, and here for this list itself.

.stat tiles

Big-number build metrics — object counts, test counts — laid out as flat tiles, no chart needed when the number does the talking.

.doc-list

A definition-style list for linking out to the repo's own markdown docs, each entry with a title and a one-line description.

A numbered list style for the lessons index — each entry shows a number badge, a title, and the concept it teaches.

code-caption + highlight

Every real code excerpt on this site is preceded by a .code-caption div naming the exact repo-relative file path, immediately above a Rouge-highlighted fenced code block — exactly as used throughout this page and every lesson.
