# Deploy Passport Seva Kendra into your own org

This is the Salesforce side of the platform — an SFDX (source-format) project
teaching "few objects, many fields" data modeling, sharing/security, Apex
automation, and testing, all built against one realistic app: an Indian
passport-office case-management system. You can deploy the whole thing into
your own free Developer org or a scratch org and follow along with the
lessons at [salesforce.imswarnil.com/lessons](https://salesforce.imswarnil.com/lessons)
against your own copy.

## 1. Install the Salesforce CLI

```bash
npm install -g @salesforce/cli
sf --version
```

## 2. Get an org

Either a free [Developer Edition](https://developer.salesforce.com/signup) org:

```bash
sf org login web -a psk-practice
```

...or a scratch org, if you have a Dev Hub connected:

```bash
sf org create scratch -f config/project-scratch-def.json -a psk-practice -d 30
```

## 3. Deploy the app

Use the curated manifest, not the root `manifest/package.xml` — that one was
generated by a full-org retrieve of the original build org and drags in
unrelated CRM Analytics/Wave/Discovery AI metadata that isn't part of this
app and may not even deploy cleanly into a fresh org.

```bash
sf project deploy start --manifest manifest/package-psk-core.xml --target-org psk-practice
```

If it reports a missing dependency (a lookup field pointing at something not
in the manifest, for instance), add that type/member to
`manifest/package-psk-core.xml` and re-run — deploys are idempotent.

## 4. Things metadata deploy can't finish for you

- **Approval process activation.** `Passport_Application__c.Diplomatic_Official_Grant_Approval`
  deploys but Salesforce does not allow a brand-new approval process to
  deploy pre-activated. Go to **Setup → Process Automation → Approval
  Processes**, open it, and click **Activate**.
- **Permission set assignment.** Deploying a permission set doesn't assign it
  to anyone. Assign yourself whichever of the `PSK_*` sets matches the role
  you want to explore (`PSK_Officer`, `PSK_Granting_Officer`,
  `PSK_Office_Manager`, etc.) under **Setup → Users → Permission Set
  Assignments**, or:
  ```bash
  sf org assign permset --name PSK_Officer --target-org psk-practice
  ```
- **Sample/demo data.** The app ships empty. `scripts/apex/02-generate-demo-data.apex`
  generates fictional Citizens, Applications, Passports, etc. — review it,
  then run with `sf apex run --file scripts/apex/02-generate-demo-data.apex
  --target-org psk-practice`. `scripts/apex/99-cleanup-demo-data.apex` reverses it.
- **Experience Cloud (the "Internal Zone" community / onboarding site).**
  Not in `package-psk-core.xml` at all — a Digital Experience site needs My
  Domain deployed and a site actually created through **Setup → Digital
  Experiences → All Sites → New** before its metadata can be deployed on top,
  which isn't something a metadata deploy alone can bootstrap into a fresh
  org. Treat this as an optional, separate, manual phase; the lessons don't
  depend on it.
- **Read-only public demo (`/demo-org` on the live site).** That's a separate,
  optional feature of *this* deploy for whoever runs the public site — see
  [SETUP_ORG.md](SETUP_ORG.md). Nothing about practicing in your own org
  requires it.

## 5. Run the tests

```bash
sf apex run test --test-level RunLocalTests --result-format human --code-coverage --target-org psk-practice
```

## 6. Open it

```bash
sf org open --target-org psk-practice
```

## What NOT to copy into your own org

`force-app/main/default/connectedApps/N8N.connectedApp-meta.xml` has a real
Consumer Key committed in this repo's git history from the original build
org. It's excluded from `package-psk-core.xml` already — don't add it back,
and if you fork this repo publicly, consider that key already
exposed/rotated rather than secret. `force-app/main/default/permissionsets/PSK_Auditor_Read_Only.permissionset-meta.xml`
*is* included and *does* expose PII-shaped fields (email, mobile, DOB) by
design — it's meant for an internal, authenticated auditor role in your own
org, not for anything public-facing. The narrower `PSK_Demo_Read_Only` set is
the one safe to ever expose to the public internet (see SETUP_ORG.md) — the
two are not interchangeable.
