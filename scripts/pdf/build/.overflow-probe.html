What the org can do end to end

  • Hold a passport application through its entire declared lifecycle on one object — Passport_Application__c — with twelve Status__c values from Draft to Delivered, six record types (Fresh, Re-issue, Tatkal, Lost/Damaged, Minor, Diplomatic/Official) and a Path that renders the stage bar on the record page.
  • Save a half-finished form. Drafts are deliberately saveable with almost nothing filled in; the four validation rules only bite once Status__c leaves Draft, which is the whole point of the "a draft is the same object in Draft status" design.
  • Carry a golden identity record separate from the application. Citizen__c is the current truth about a person; the application keeps its own as-submitted copy of the applicant's details (see the Data Model section for why that duplication is intentional).
  • Model the fulfilment tail end to end in metadata: Passport__c (the issued booklet, with its own Ordinary / Diplomatic / Official record types), Print_Job__c and Dispatch__c — with booklet pages, validity, ECR, category, place of issue and the delivery address all derived by cross-object formula rather than re-keyed.
  • Price an application without code. Fee_Matrix__mdt carries a record per record-type × booklet-pages × validity combination, and SLA_Config__mdt carries a normal and a Tatkal target for every processing stage.
  • Enforce role- and criteria-based visibility. A role hierarchy, public groups, work queues and criteria-based sharing rules route Tatkal, high-risk, diplomatic, granting-stage and fulfilment-stage records to the right teams without opening the org up.
  • Present a purpose-built app. The Application Management Console has a branded navy header, a curated tab set, a custom Lightning home page and four LWCs (home dashboard, application sidebar, sidebar summary, risk meter) backed by Apex controllers with test classes.
  • Reuse picklist vocabulary. Shared value sets — Indian states, gender, region, payment mode/status, document status, fulfilment status, courier partner, relationship, severity, language — are Global Value Sets, so a new object inherits the vocabulary instead of re-declaring it.

What it still cannot do

  • No approval anywhere. Granting a Diplomatic or Official passport is currently a picklist change by anyone with edit access — there is no Approval Process in the org at all.
  • No citizen self-service. There is no Experience Cloud site for applicants; every step of the journey is staff-mediated. The inherited Internal Zone community and its self-registration controllers are template leftovers, not a PSK applicant portal.
  • No reporting. Zero reports, dashboards or custom report types exist for any PSK object, so there is no way to answer "how many applications are stuck at Police Verification" other than a list view.
  • No region-based sharing. Enterprise Territory Management is not enabled and cannot be enabled by deploy, and criteria-based sharing cannot read PSK_Office__r.Region__c through the lookup — so office/region scoping is unimplemented.
  • No field-level encryption. Shield Platform Encryption is unavailable in Developer Edition, so Aadhaar_Token__c is stored as plain text.
  • No integrations. n8n, Twilio and the AI enrichment layer are designed for but not built; Notification_Log__c exists and is empty of real sends.
  • No visa department. Visa_Application__c, Country__c and Sponsor__c are unbuilt, although a Visa Processing Team role, a PSK Visa Team public group and a PSK_Visa_Type global value set are already in place waiting for them.
  • No localisation. Every objectTranslations/ bundle is an en_US stub echoing the English label, despite Citizen__c.Preferred_Language__c existing to record a citizen's language preference.

Data model

Six objects carry the weight of the system. Passport_Application__c sits at the centre with 56 fields, 6 record types and 13 validation rules — the “few objects, many fields” philosophy in one place. Everything else either identifies a person, records an issued booklet, or tracks fulfilment.

Why the application duplicates the applicant's details

Passport_Application__c carries its own First_Name__c, Last_Name__c, Date_of_Birth__c, Mobile__c and full address even though it also has a Citizen__c lookup to the golden identity record. That is deliberate, not an oversight.

A passport application is a legal instrument. The details as declared at submission are what get printed into the booklet, what the police verify against, and what an audit or a court would later be asked to examine. They are a snapshot of a declaration made on a date, not a live view of a person.

If those fields were cross-object formulas reading Citizen__r, then the day a citizen moved house or corrected a spelling, every historical application would silently rewrite itself — including applications already granted and printed. The record of what was declared would be destroyed by the act of keeping the citizen record current. Snapshotting is the only correct answer.

Citizen__c therefore answers "who is this person now"; the application answers "what did they declare then". Both are needed, and they are allowed to disagree.

Where duplication is avoided

  • Passport__c re-keys nothing from the application. Booklet_Pages__c, Validity_Years__c, ECR_Status__c and Passport_Category__c are TEXT(Application__r.…) formulas, Holder_Name__c is assembled by formula from the application's name parts, and Place_of_Issue__c is PSK_Office__r.Name. The booklet's own facts — file number, issue and expiry dates, status — are the only stored fields.
  • Dispatch__c builds Delivery_Address__c as a formula over Passport_Application__r's address lines, so a courier label can never drift from the application it was raised against.
  • Family_Member__c reads Member_Date_of_Birth__c and Member_Mobile__c through Related_Citizen__r, and Display_Name__c falls back to a typed Member_Name__c only when there is no linked citizen record to read from.
  • Print_Job__c and Dispatch__c both expose ARN__c as Passport_Application__r.Name rather than storing the ARN string.
  • The rule of thumb the model follows: snapshot a declaration, derive a fact.

The org has 3 Salesforce licences, all 3 in use, and 3 Salesforce Platform licences with 1 in use — 2 free. There is no room to stand up one user per persona.

Persona testing therefore uses a single Salesforce Platform user with permission sets swapped between passes, rather than six or seven dedicated users. Assign one PSK_* set, run that persona's rows in the access matrix, remove the set, assign the next.

Two consequences to be honest about. First, a swapped-set user does not prove that concurrent personas see the right things — anything that depends on record ownership by a different user (queue assignment, the owner-based half of the role hierarchy) needs a second real user, and there are two Platform licences available for exactly that.

Second, the Salesforce Platform licence itself withholds some objects and features that a full Salesforce licence grants. Do not read a Platform-user access failure as a permission-set bug until the licence has been ruled out.

A. Deploy, verify and seed command sequence

Run from the repository root. psk-dev is the project's default target-org, so --target-org is optional throughout.

1. Validate before you touch the org

sf project deploy start --source-dir force-app --dry-run
Full validation, nothing saved. Always do this first.
sf project deploy start --source-dir force-app/main/default/objects --dry-run
Narrower and much faster while iterating on the data model.

2. Deploy, in dependency order

sf project deploy start --metadata GlobalValueSet
Value sets first — picklist fields reference them.
sf project deploy start --source-dir force-app/main/default/objects
Objects, fields, record types, validation rules, compact layouts, list views.
sf project deploy start --source-dir force-app/main/default/layouts --source-dir force-app/main/default/flexipages
Layouts and Lightning pages, once the fields they reference exist.
sf project deploy start --metadata Role
Roles before groups — groups reference roles.
sf project deploy start --metadata Group --metadata Queue
Public groups and work queues.
sf project deploy start --metadata PermissionSet --metadata PermissionSetGroup
Personas. Field-level security lives here.
sf project deploy start --metadata SharingRules
Sharing rules last — they reference groups, roles and fields.
sf project deploy start --metadata CustomMetadata
Fee_Matrix__mdt and SLA_Config__mdt records.
sf project deploy start --source-dir force-app/main/default/lwc --source-dir force-app/main/default/classes
Apex and LWC.
sf project deploy start --metadata CustomApplication --metadata CustomTab --metadata PathAssistant
App shell, tabs and the Path.

3. Verify

sf apex run test --test-level RunLocalTests --result-format human --code-coverage
Whole local suite with coverage.
sf apex run test --class-names PSK_HomeControllerTest --result-format human
A single class while iterating.
sf data query -q "SELECT COUNT(Id) FROM Passport_Application__c"
Confirm rows are visible to the running user.
sf org open --path lightning/app/Application_Management_Console
Open the app and eyeball the home page and tab set.
sf org open --path lightning/setup/FlexiPageList/home
Lightning App Builder — do the manual per-record-type page activations (P1-03).

4. Seed demo data

sf data query -q "SELECT COUNT(Id) FROM Passport_Application__c"
Baseline count before seeding, so the delta is provable.
sf apex run --file scripts/apex/seed-demo-data.apex
Anonymous-Apex seed at scale 1 (~1,200–1,500 records). Check the exact script name in scripts/apex/.
sf apex tail log --color
Watch it run; a storage failure shows up here, not in the CLI exit code.
sf org open --path lightning/setup/CompanyResourceDisk/home
Storage usage page — confirm you have not hit the 5 MB ceiling.

5. Retrieve back

sf project retrieve start --manifest manifest/package.xml
Full-org retrieve. Slow — nearly 200 wildcard types (see P2-04).
sf project retrieve start --metadata CustomObject:Passport_Application__c
One object, which is what you usually want.
